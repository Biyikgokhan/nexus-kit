# Contributing

Small, reviewable changes help the most.

1. Describe the user problem in an issue, especially for protocol changes or new dependencies.
2. Fork and branch, then `npm ci`.
3. Add meaningful tests for data handling, export, protocol or security behavior.
4. Run `npm test`, `npm run build:wizard`, `npm pack --dry-run`.
5. Open a PR with behavior, validation, limitations and screenshots for visible changes.

Use English in code and TR/EN wording for new wizard features. Explain added dependencies and keep package-lock.json current. Never commit private references, credentials, commercial music or artwork without redistribution rights.

Contributions follow [NOTICE.md](NOTICE.md). Use `git commit -s` when you can make the Developer Certificate of Origin assertion. Automation must not invent a human sign-off. Copyright is not transferred.
